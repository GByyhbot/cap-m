# MADOW X DIAN115 回调服务器规范 v1

本规范供回调服务提供方接入使用。播放器用户只需分别填写服务器域名和 MADOW API Key；插件默认使用 HTTPS，并自动补全 `/api/portal/player/v1/virtual-cache`，作为下文的基础地址。播放器持有自己的 115 Cookie，直接向 115 取链和转存。回调服务器不接收 Cookie，不代理视频，也不代用户转存。已有完整接口地址继续兼容，不会重复拼接。

参考实现位于 license-server：基础路径 `/api/portal/player/v1/virtual-cache`。DIAN115 内部使用独立的加密 SDK 接口 `/api/portal/openapi/virtual-cache/player-{query,resolve,stats}`，独立回调不需要该私有 SDK。原有 `/api/portal/openapi/virtual-cache/query` 的元数据协议保持原样。

## 共通约定

- 方法均为 `POST`，请求和响应为 JSON；响应使用 `Cache-Control: no-store`，不重定向携带凭据的请求。
- 请求头：`Content-Type: application/json` 和 `X-OpenAPI-Key: 用户的 MADOW API Key`。不要把密钥放在 URL、资源 ID、日志或图片地址中。
- 每次调用均校验密钥是否有效、暂停，用户是否可用以及 VIP、权限和限流状态。license-server 对此网关使用固定 `madow-player` 应用权限，默认仅允许查询和解锁；不开放普通 SDK 的其他操作。普通 SDK 原来的关闭状态不变。
- 查询仅匹配公开、审核通过的普通 115 资源，排除失效分享、离线链接和未确认悬赏。不得将不匹配媒体类型、私有或未审核的资源经播放器接口暴露。
- 文件 ID、目录 CID 按字符串原样传输，不经过 JavaScript 数字转换。文件名是远端元数据，`/`、`\` 都是名称的一部分。
- `file_size` 单位为字节，`sha1` 为 40 位十六进制文件指纹。它们用于内部去重和视频信息缓存匹配，播放器不展示文件大小。
- 独立回调不返回 `parent_id`、相对路径、祖先目录、账号目录或整个原始数据库行。只返回文件名、文件身份及获取分享参数必需的引用。
- 成功为 HTTP 200、`code: "ok"`。错误必须使用非 2xx，不能把鉴权/解锁失败伪装为空结果。

## 1. 查询资源：`POST <基础地址>/query`

```json
{"tmdb_id": 101, "media_type": "tv", "page": 1, "size": 200}
```

`tmdb_id` 必须为正整数；`media_type` 为 `movie` 或 `tv`，不能仅凭编号匹配。分页默认 1/50，单页最大 200。请求只读，禁止自动解锁、扣点、转存、在线扫描 115 或返回临时播放链接。

```json
{
  "code": "ok",
  "data": {
    "tmdb_id": 101,
    "type": "tv",
    "items": [
      {
        "entry_key": "opaque-file-reference",
        "share_id": 123,
        "locked": true,
        "file_name": "示例.S01E02.2160p.HDR10.mkv",
        "file_size": 8589934592,
        "sha1": "0123456789ABCDEF0123456789ABCDEF01234567",
        "file_id": "9007199254740993001"
      }
    ],
    "page": 1,
    "size": 200,
    "total": 1,
    "has_more": false
  }
}
```

`entry_key` 是服务端可验证的缓存文件引用；`share_id` 用来标识对应分享。二者都不应由客户端反推分享码。未解锁条目不得返回 `share_code` 或 `receive_code`。已有授权的条目返回 `locked:false`，并附上这两个字段，其中空提取码必须明确为 `""`。客户端只在内部用锁定状态决定是否获取参数，不在资源行展示状态。

查询条目还返回发布者标记：

```json
{"share_seasons":[3],"share_episodes":[1,2,3],"share_tags":["4K","HDR10","HEVC"],"share_file_count":3,"share_video":{"resolution":"4K","hdr":"HDR10","video_codec":"HEVC"}}
```

季集为非负整数数组，未知用空数组；只有明确标记的 0 才表示特别篇，不能把剧集主条目的默认季号当成明确标记。`share_file_count` 是当前媒体下同分享可用文件总数，不是本页数量。同分享重复发布时可复用已有授权，但发布标记必须属于文件绑定的来源，不能混用另一个季条目的标记。视频标记来自该分享条目填写的参数，按维度覆盖其下全部文件。`share_video` 保留明确的参数维度，支持 `resolution`、`hdr`、`video_codec`、`video_bit`、`audio_codec`、`audio_effect`、`source`、`frame_rate`，也可保留其他非空标记。未知参数省略，不能填写空占位覆盖有效数据。客户端先应用条目标记，再用 FFP 和文件名补齐缺失维度；`share_tags` 兼容旧回调。HDR 分类与展示必须使用同一合并结果。

单季分享直接使用分享季号，只补文件集号；明确的单集标记直接使用。多个文件不把整季集号套给每个文件。多季分享按文件解析季集，电影忽略季集、只解析视频参数。resolve 响应也应保留可获得的发布标记。

`total` 为可见缓存候选数；损坏或不可用的条目可能被省略，单页允许空 `items` 且 `has_more:true`，客户端仍按页码递增。无结果用空数组及 `has_more:false`。最多自动读取 100 页，超过时报告错误，不悄悄返回不完整结果。

独立回调按文件名解析季集和视频标签，不需要目录层级。无法可靠解析的剧集不得猜成第 1 季、第 1 集。支持特别篇季号 0。

## 2. 获取完整参数：`POST <基础地址>/resolve`

仅在播放器请求播放，或用户在转存模块明确确认后调用。

```json
{"tmdb_id": 101, "media_type": "tv", "entry_key": "opaque-file-reference", "purpose": "playback"}
```

`purpose` 只能为 `playback` 或 `transfer`。服务端必须重新校验文件引用、TMDB 编号、媒体类型、分享指纹、公开审核状态和当前用户资格，在扣点前完成核对。引用换绑到其他分享或媒体时必须拒绝。沿用站点正常解锁流程中的积分、VIP 免费规则、解锁券、禁用状态和每日额度，不新增另一套扣费逻辑；已有授权直接复用，不重复扣点或登记解锁。

```json
{
  "code": "ok",
  "data": {
    "entry_key": "opaque-file-reference",
    "share_id": 123,
    "locked": false,
    "file_name": "示例.S01E02.2160p.HDR10.mkv",
    "file_size": 8589934592,
    "sha1": "0123456789ABCDEF0123456789ABCDEF01234567",
    "file_id": "9007199254740993001",
    "share_code": "examplecode",
    "receive_code": "abcd"
  },
  "already": false,
  "owner": false
}
```

所有取链及单文件转存所需的分享参数都必须完整返回；缺少分享码或有效文件 ID 就不能报告成功。`already` 和 `owner` 为操作结果，资源页面不显示这些标记。不得在返回中夹带站点或其他用户的 115 Cookie。

播放器每次取流优先使用已有参数。如果当前候选全都缺少参数，只按配置的优先资源序号解锁一条分享，不批量解锁全部候选，也不在失败后静默解锁下一条。一次解锁后的重复调用应由原流程幂等处理。查询结果中不得夹带临时播放 URL；播放器直接从115取得的直链另存到本机加密缓存。

## 3. 今日已解锁：`POST <基础地址>/stats`

请求为 `{}`。不进行查询、解锁或转存副作用。

```json
{"code":"ok","data":{"today_unlocked":3,"day":"2026-10-20","timezone":"Asia/Shanghai"}}
```

以服务器北京时间的当日范围统计当前用户的解锁记录，按 `share_id` 去重；同一分享多个文件、重复播放或重复取参数均不重复统计。历史已解锁分享当天再次播放不新增次数。分享者自己使用自己的资源不创建解锁记录。该数值显示在播放器插件说明页，不显示在资源行。

## 4. 失效清单：`POST <基础地址>/exports`

使用同一密钥鉴权，仅在用户明确点击导出时调用。报告来自客户端，站点收到后须另行核验，生成报告不能自动修改资源状态。

```json
{"version":2,"share_ids":[123,456]}
```

上限 512 KiB、2000 个 ID，ID 必须是正整数且不超过 JavaScript 安全整数上限。服务端去重，拒绝未知字段和旧版完整资源报告。请求和下载内容均只有版本号与站点分享 ID 列表；不接收分享码、链接、文件名、Cookie、API Key、提取码或目录层级。DIAN115 本地失败不导出，经 DIAN115 获取的站点来源可导出其站点 ID；来源不明确的历史记录不导出。成功响应：

```json
{"code":"ok","data":{"token":"64位小写十六进制随机值","expires_in":600}}
```

下载：`GET <基础地址>/exports/<token>`。以不可猜测的 256 位随机令牌授予十分钟只读下载能力，无需密钥头。过期或未知令牌返回 404；有效令牌返回 JSON 附件、`Cache-Control:no-store`、`Referrer-Policy:no-referrer`。令牌应从访问日志中脱敏。参考实现进程内最多保存 32 份/16 MiB，重启失效；容量已满返回 503，不挤掉尚未过期的报告。

## 客户端执行边界

- 查询结果默认缓存 120 秒，可设 15–600 秒；空结果缓存 10 秒，错误不缓存。同一媒体不同季集共用结果，按服务地址、用户密钥和站点开关隔离。容量默认 8 MiB，可设 1–64 MiB，先清理查询缓存，再清理较早媒体及分享参数。最近媒体和影片资料最多七天；失效及转存安全记录独立保留。
- 同一分享取得参数后，其他文件复用分享码和提取码，各自保留文件 ID，播放和转存不重复请求 resolve。直链独立加密缓存，最迟于请求发起后两小时失效，115返回的到期时间更早则提前失效。URL `t` 等明确到期参数和响应绝对到期字段、`expires_in` 取最早值；无法确认到期时间时不缓存，已过期响应不播放。相同文件参数的并发取链合并，按服务与 Cookie 隔离。
- 转存按 TMDB 媒体展示海报、简介，剧集再按季、HDR 和单集进入，所有文件保留独立转存入口。每页 `childItems` 只有一层。
- 转存确认会话 10 分钟、单次确认 2 分钟，仅以认证加密形式保存在播放器本机，不放进资源链接。查询数据、115 分享参数和链接、安全记录同样加密；缓存密钥由服务 API Key 派生，只在运行内存中。直链与其他115信息同样加密。宿主重建运行环境后需通过模块重新载入配置。宿主设置项是否加密由播放器负责。
- 播放器用自己的 Cookie 请求 `GET https://proapi.115.com/os_windows/2.0/share/downurl`，参数为 `share_code`、`receive_code`、`file_id` 和 `cid=0`，不覆写播放器默认 UA；直链有效期内复用缓存，到期重新取链。
- 确认转存后，播放器向 `POST https://webapi.115.com/share/receive` 提交表单 `share_code`、`receive_code`、`file_id`、目标目录 `cid`、`is_check=0`。同分享每组最多 50 个文件 ID 用逗号连接。没有有效文件 ID 或目录 CID 就不发请求，禁止退化成整份分享转存。
- 整类转存按集号、内容与参数去重，已有授权能覆盖的集数不为合并请求额外解锁，其余优先同分享覆盖更多集数；不同组串行提交，两次起始时间至少相隔 1.5 秒。没有宿主定时器时保存进度，间隔满足后明确继续，不忙等或使用未公开 API。
- 115 转存提交后如果超时、网络中断或返回格式损坏，结果视为未知，记录到本机并停止。禁止盲目重试或改用另一条分享继续提交。
- 成功或结果未知时，同账号、同内容或参数和同目录七天内不重复提交。只有明确的资源失效错误才屏蔽整份分享，过滤后续资源并允许导出清单；登录、目录、空间和限流错误不误屏蔽分享。

## 错误与验收

常见状态：400 参数无效；401 密钥或账号/VIP 不可用；403 权限或解锁禁用；404 文件引用不可用；429 超出查询或解锁额度；503 服务未启用。解锁失败保留原站点业务错误，避免让用户误判为无资源。

至少验证：查询前后余额和解锁数不变；首次播放/确认转存才调用 resolve；同一分享的两个文件只产生一条解锁记录；重复调用不重复扣点；不匹配媒体、私有/未审核资源不可读取或解锁；空提取码和大文件 ID 不丢失；资源行无解锁标记；Cookie 不出播放器到 115 的请求边界；转存结果未知时不会自动重复提交。
